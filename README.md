# AlgoNote · 刷题手记

一个轻量、单用户的算法刷题仓库：保存牛客和 LeetCode 的题目与自己的解答，根据参考代码生成中文解析，在浏览器里独立重做。

**当前版本：v0.1.1。** 本地首次部署与验收步骤见 [LOCAL_DEPLOYMENT.md](LOCAL_DEPLOYMENT.md)。

源码仓库：[volcano-code/OJ](https://github.com/volcano-code/OJ)。[查看 CI 运行记录](https://github.com/volcano-code/OJ/actions/workflows/ci.yml)。

**只支持 C++17 和 Python 3。** 一个 Python 服务、一个 SQLite 数据库、一套无构建步骤的网页；运行提交的代码时使用独立 Docker 容器。

## 已实现的功能

- 录入、编辑、搜索题目；按来源、算法标签和掌握状态筛选。
- 每题保存 C++ / Python 参考代码和练习模板，可以只提供其中一种语言。
- 根据参考代码辅助识别函数名、参数和返回值；识别结果可以手动修正。
- 函数模式和标准输入输出模式；数组、二维数组、字符串、链表、二叉树和原地修改。
- 按实际参考代码生成中文题解；支持手动编写、编辑和历史版本。
- 题面、参考答案、签名或测试变化时，将对应的旧题解标记为过期。
- 重做时隐藏答案，按题目与语言自动保存草稿；同题多标签页发生冲突时保留编辑内容并要求明确处理，保存中继续输入的最新文本也会继续提交。
- 运行样例、提交全部已配置测试、检查参考答案、回看提交记录。
- SQLite 持久化；题面、源码、题解和测试同时写入可提交到 Git 的 `notebook/` 文件夹。
- 导出 ZIP 备份；恢复题目、题解、草稿、历史版本与完整提交记录。
- 单用户访问口令、跨站写入限制、题目版本冲突检测。
- GitHub Actions 工作流，可在有 Docker 的 CI 环境运行真实容器集成测试。

## 当前交付边界

本仓库包含完整源码和本地部署配置。AI 服务需要在本机配置，网页默认只监听 `127.0.0.1`；公网部署需要另行配置。

| 条件 | 可以使用的功能 |
| --- | --- |
| 安装 Python 依赖并启动 | 题库保存、检索、代码编辑、草稿、手写题解、导入导出 |
| Docker 服务及执行镜像就绪 | C++ / Python 真实编译执行、样例与扩展测试 |
| 配置兼容的 AI 服务 | 根据自己的参考代码自动生成中文解析 |

未配置的能力会显示明确状态。程序不会将模拟运行当作真实评测，也不会在模型未配置时生成假题解。

## 1. 启动

### 环境

- Python 3.11 或更新版本。
- 在线运行代码需要 Docker 已安装并启动，且当前用户可执行 `docker info`。
- 首次安装需要下载 Python 依赖；首次构建执行镜像需要下载基础镜像和编译器。
- 主启动脚本适用于 Linux、macOS 或 WSL 的 Bash 环境。

从 GitHub 获取源码并启动：

```bash
git clone https://github.com/volcano-code/OJ.git
cd OJ
bash start.sh
```

使用源码压缩包时，进入解压后的源码根目录，再运行 `bash start.sh`。

脚本会建立 `.venv`、安装锁定的直接依赖、在首次启动时复制 `.env.example` 为 `.env`，并在 Docker 可用时构建执行镜像。镜像按当前执行代码指纹检查，更新后会重建过期镜像；使用 `.env` 配置的镜像名称。

打开：**http://127.0.0.1:8000**

如果 Docker 尚未就绪，网页仍能启动并保存题目，但运行按钮会返回执行服务未就绪。Docker 就绪后，在项目目录执行：

```bash
.venv/bin/python -m algonote prepare-runner
.venv/bin/python -m algonote doctor --run-check
```

### 手动启动

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m algonote prepare-runner
.venv/bin/python -m algonote serve
```

已有 `.env` 时保留原文件。后续启动只需要最后一条命令。

## 2. 先导入演示题，检查操作流程

项目附带三道明确标记的演示题：两数之和、多组整数求和、反转链表。它们同时提供 C++ 与 Python 参考答案，覆盖函数、标准输入输出和链表适配。

在另一个终端中执行：

```bash
.venv/bin/python -m algonote import examples/starter.json
```

也可以在网页中点击「设置 → 导入备份」，选择 `examples/starter.json`。已有 ID 会被跳过，重复导入不会覆盖自己的修改。

## 3. 添加自己的题目

点击「录入题目」，粘贴题面和参考答案，选择牛客或 LeetCode。

1. 至少填写一种语言的参考代码。
2. 点击「识别函数与模板」。函数名、参数类型和返回类型会被填入运行设置，请核对识别提示。
3. 添加题目样例，填写输入和预期输出。需要补充边界测试时，可以取消该用例的「样例」标记。
4. 保存题目。详情页可以查看参考代码、检查答案、写题解或进入重做。

题目来源不会固定执行模式：牛客也有函数题，具体以题目要求为准。

### 函数题的测试输入

输入是**按函数参数顺序排列的 JSON 数组**。

例如函数 `twoSum(nums, target)` 的两个参数：

```json
[[2, 7, 11, 15], 9]
```

预期输出：

```json
[0, 1]
```

只有一个数组参数时，仍需外层参数数组。例如 `reverseList(head)` 的输入：

```json
[[1, 2, 3]]
```

空链表是 `[[]]`。二叉树参数用层序数组表示，例如 `[[1, null, 2, 3]]`。

### 标准输入输出题

输入和预期输出填写普通文本，不需要 JSON 引号。C++ 参考代码应包含 `main`，Python 代码负责读取标准输入并打印结果。

### 支持的类型

| 表单类型 | Python | C++ |
| --- | --- | --- |
| `int` | `int` | `int`，输入按有符号 32 位范围检查 |
| `int64` | `int` | `long long`，有符号 64 位 |
| `float` | `float` | `double` |
| `bool` | `bool` | `bool` |
| `str` | `str` | `string` |
| `char` | 单字符字符串 | ASCII `char` |
| `[]` / `[][]` | 一维 / 二维列表 | 对应 `vector` |
| `ListNode` | 自动提供节点定义 | 自动提供节点定义 |
| `TreeNode` | 自动提供节点定义 | 自动提供节点定义 |
| 返回 `void` | 检查调用后指定参数 | 检查调用后指定参数 |

普通类方法默认使用 `Solution`，全局函数将类名留空。代码中自行提供节点定义时会尽量保留原定义；需要符合常见的 `val/next` 或 `val/left/right` 接口。

C++ 签名识别属于辅助功能，不是完整编译器前端。复杂模板、自定义容器、多方法设计题、交互题、SQL 题和自定义特殊判题器不在首版范围内。`vector<float>` 与执行模板的 `vector<double>` 等类型差异会提示核对；必要时使用完整标准输入输出程序。

## 4. 配置 AI 中文解析

编辑项目目录的 `.env`：

```dotenv
ALGONOTE_AI_BASE_URL=你的兼容接口根地址（通常包含 /v1）
ALGONOTE_AI_API_KEY=你的接口密钥
ALGONOTE_AI_MODEL=该服务实际支持的模型名称
```

填写后重启服务。接口必须兼容 `POST /chat/completions`，也可以将完整的 `/chat/completions` URL 作为地址。支持无需密钥的本地兼容服务，例如地址为 `http://127.0.0.1:11434/v1` 的配置；模型仍需由你实际安装并提供。

选择题目详情中的「题解」，切换语言后点击生成。系统使用对应参考代码、题面、样例和这份参考代码已有的验证结果生成解析。生成仅由你的点击触发，读取已保存题解不会再次调用模型。

生成内容包含核心思路、关键步骤、样例演示、正确性说明、复杂度与易错点。它可以编辑，并与当时的代码和测试版本绑定。没有验证结果时，应明确说明尚未运行；测试失败时，先解释失败证据。

`.env` 已加入 Git 忽略列表，AI 凭据不会放入网页、题目导出或备份中。更换服务或模型只需要修改配置。

## 5. 在线重做与结果含义

点击「再做一次」，代码区显示练习模板或上次草稿，参考答案和题解默认收起。

- 「运行样例」只执行标记为样例的测试。
- 「提交测试」执行本题所有已配置测试。
- 草稿按题目和语言分别保存，切换语言会恢复对应草稿。
- 每次运行保存代码、题目版本和结果；详情页可以查看历史。

页面中的「通过已有测试」只说明本项目已配置的用例通过，不能代替原平台完整评测。项目不获取或声称拥有原平台隐藏测试。

支持的比较规则：

| 规则 | 适用场景 |
| --- | --- |
| 精确比较 | JSON 结构与值相同；标准输出仅规范化 CRLF 和末尾换行 |
| 外层数组无序 | 只忽略最外层元素顺序，重复次数仍然重要 |
| 空白分隔 | 标准输入输出题，忽略 token 之间的空白差异 |
| 浮点容差 | 数值按相对或绝对误差 `1e-6` 比较 |

参考答案和重做代码可以采用不同算法。判断依据是输出与对应规则，不比较代码是否相似。

## 6. 数据和 Git 仓库

| 位置 | 内容 |
| --- | --- |
| `data/algonote.sqlite3` | 权威数据库：题目、草稿、解析、版本、提交 |
| `notebook/problems/<题目ID>/` | 每题的 `problem.json`、`statement.md`、参考代码、题解和 `tests.json` |
| `examples/starter.json` | 可选演示题 |
| `algonote/static/` | 无外部 CDN 依赖的网页 |
| `algonote/runner*.py` | 独立执行服务适配与容器入口 |

题目保存后会同步写入 `notebook/`。同步读取与写入会串行处理，避免较早的请求覆盖新版本文件；删除题目后也不会被旧同步任务重新创建。这个目录可以提交到你的 GitHub 仓库；数据库与 `.env` 默认被忽略。**网页修改由数据库保存，直接修改磁盘上的镜像文件不会自动更新网页。** 单题文件可以用下列命令导入；已有 ID 将跳过，避免无意覆盖。

```bash
.venv/bin/python -m algonote import path/to/problem.json
```

新的外部题目文件可省略 `id`，导入时自动分配。日常修改已有题目请使用网页编辑。当前版本没有自动推送 GitHub、没有存储 GitHub 令牌。

### 完整备份

网页「设置 → 导出完整备份」，或：

```bash
.venv/bin/python -m algonote export backups/algonote-backup.zip
```

ZIP 包含易读文件和 `backup.json`。恢复时导入 `backup.json`，会保留草稿、全部提交和历史版本。界面显示最近 100 次提交，完整备份包含更早的记录。

一次导入最多 16 MiB、2000 道题。非法内容会整批拒绝；已有题目 ID 会被跳过，保留当前数据。首次将备份恢复到空数据库即可恢复全部内容。

SQLite 数据库提交成功后若文件镜像写入失败，页面会明确说明「数据已保存到数据库」，可以刷新查看或使用完整导出备份。请修复磁盘空间或目录权限后再保存题目，以重新同步文件。备份导入成功但镜像同步失败时，重新导入同一份备份会跳过数据库中已有题目并补齐这些镜像文件。

## 7. 在另一台设备访问

默认只监听 `127.0.0.1`。需要在自己的服务器或局域网访问时，先在 `.env` 设置较长、随机的个人口令：

```dotenv
ALGONOTE_HOST=0.0.0.0
ALGONOTE_TOKEN=自行设置的长随机口令
```

重启后，在页面「设置」中填写同一口令。公网部署还应配置 HTTPS。此版本以单用户自用为目标，不包含多用户账户、共享题库或公开代码执行服务的运营功能。

## 8. 验证

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

在有 Docker 的环境执行真实容器验证：

```bash
.venv/bin/python -m algonote prepare-runner
ALGONOTE_DOCKER_TESTS=1 .venv/bin/python -m pytest -q
```

无需安装开发测试依赖时，可以先运行 `.venv/bin/python -m algonote doctor --run-check`。它实际测试两种语言的函数与输入输出模式；Docker 不可用会返回未执行和非零退出码。添加 `--json` 可获得不含密钥的报告。AI 配置只检查是否填写，不会自动调用外部模型。

普通测试包括真实执行固定开发测试程序的 Python / g++ 适配验证、API、SQLite 恢复、草稿、版本冲突、AI 错误处理与输出比较。实际上传的代码始终只交给 Docker，没有宿主机执行回退。

Docker 测试覆盖两种语言、函数与输入输出、超时、输出上限、非 root、只读根文件系统和网络隔离。测试报告中的跳过不会视为通过。交付时的实际验证结果见 [VERIFICATION.md](VERIFICATION.md)。

执行默认限制为每条测试 2 秒、进程地址空间 256 MiB、标准输出与错误合计 64 KiB。容器另有限制：1 CPU、512 MiB 内存、64 个进程、无外网、不挂载宿主机目录。

## 常见问题

**代码执行服务未就绪。** 执行 `docker info`，确认当前账户能使用 Docker；然后构建 `Dockerfile.runner`。不要以关闭隔离作为解决方式。

**参考代码在原平台能通过，这里编译失败。** 检查是否选择了正确执行模式、函数名、参数类型和节点定义。读取完整编译信息；复杂平台专用接口可能需要补齐适配。

**AI 题解无法生成。** 检查 `.env` 的地址、模型和密钥，修改后重启。认证、限流、超时和返回格式错误会有分别对应的提示。

**打开网页出现访问口令要求。** 在「设置」输入服务端配置的 `ALGONOTE_TOKEN`。口令只在当前浏览器会话保存。

**保存时提示版本冲突。** 题目已经被另一个页面修改，先保留当前输入，再刷新最新版本后编辑，系统不会静默覆盖新数据。
